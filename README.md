# FormFaker 表单造数助手

一个 Chrome 扩展：打开测试环境的表单页，点一下就能把姓名、手机号、统一社会信用代码、注册资本、地址、日期、上传文件等测试数据填进去。字段语义由扩展根据页面标签自动推断，数据全部在本机离线生成，不发任何网络请求。

适合 QA 造数、前端联调、表单回归和演示环境准备。

> 仅用于测试环境。扩展不会自动提交表单，也不绕过验证码或服务端校验。

## 特性

- **造得真**：手机号段、身份证 / 统一社会信用代码校验位、Luhn 银行卡号、真实行政区划、经纬度、邮箱域名都按真实规则生成，能过常见的前端格式校验。
- **认得出**：综合 label、placeholder、name、id、表格列头、`aria-labelledby` 和控件周围的文本推断中文字段语义，内置 22 条规则、7 个分组。
- **填得全**：支持原生控件与 Element Plus / Ant Design 组件；覆盖文本框、下拉、多选、级联、日期/范围、单选/复选、开关、富文本、上传和弹窗选择。
- **长表单不掉队**：条件渲染区块（如选中某个类型后才出现的字段）填充后自动补扫；需要滚动才挂载的字段边滚边填，结束后恢复页面滚动位置。
- **可控**：规则中心可逐条改关键词、分组和生成方式；支持模板 DSL、词库覆盖、规则 JSON 导入导出，团队之间可以共享同一套造数规则。
- **可回退**：撤销恢复上一次填充前的值；清除全部一键置空；上传文件不参与撤销。
- **填充后可自检**：回读页面自身的校验提示，未通过的字段标黄显示页面原文；扩展自身填充失败的字段标红，两类分开计数。
- **离线与隐私**：无网络请求、无远程脚本、无统计上报；权限用途在下方逐项说明。

## 工作原理

1. **扫描**：点击图标后，内容脚本按需注入当前页，收集可填充控件，并用标签、占位符、`name/id`、表格列头等线索推断业务语义。
2. **生成**：按命中的规则在本机生成值；证照号码、银行卡等使用校验位算法，地址与经纬度来自离线行政区划数据。
3. **填充**：按控件类型选择写入方式（原生事件、组合框展开点选、日期键入、弹窗选择记录、上传文件等），并在条件区块出现后自动补扫。
4. **回读**：填充完成后读取页面自身渲染的校验提示，把「扩展没填成功」和「页面校验没通过」分开反馈。

## 安装

### 从源码构建（推荐）

需要 Node.js 20+ 与 pnpm 9+。

```bash
git clone https://github.com/xuankew/formFaker.git
cd formFaker
pnpm install
pnpm build
```

1. 打开 `chrome://extensions`，右上角开启「开发者模式」。
2. 点「加载已解压的扩展程序」，选择项目里的 `dist/` 目录。
3. 建议把扩展图标固定到工具栏。

修改代码后重新执行 `pnpm build`，再到扩展卡片上点刷新图标，并刷新已打开的业务页。

### 使用发布包（无需构建）

1. 到 [Releases](https://github.com/xuankew/formFaker/releases/latest) 下载最新的 `FormFaker-<版本>.zip`（同页附 `SHA256SUMS.txt`，可用 `shasum -a 256 -c SHA256SUMS.txt` 校验）。
2. 把 zip 解压到一个**固定目录**（扩展运行时会按需读取，目录不能删）。
3. 打开 `chrome://extensions` 并开启「开发者模式」。
4. 点「加载已解压的扩展程序」，选择解压后的目录（里面应有 `manifest.json`）。

### 升级

把新版本覆盖到原来的目录（路径不要变），在 `chrome://extensions` 点 FormFaker 卡片上的刷新图标，再刷新业务页。设置不用重配：填充行为与合成图样式存在 `chrome.storage.sync`，规则、词库与上传文件池存在 `chrome.storage.local`，都与扩展目录无关。

## 快速上手

1. **先在自带 demo 页试一遍**：地址栏打开 `chrome-extension://<扩展ID>/demo.html`（扩展 ID 在 `chrome://extensions` 的卡片上），点扩展图标 → 「填充全部」。demo 页包含原生控件、Element Plus 组件、联系人子表、弹窗选择、滚动懒挂载和上传门槛样例。
2. **再到业务页使用**：打开要造数的表单页 → 点扩展图标 → 弹窗里会列出识别到的字段（此时**只识别、不自动填**）→ 检查一遍 → 点「填充全部」。

## 弹窗里的操作

| 操作 | 说明 |
| --- | --- |
| 重新识别 | 页面结构变化（切换步骤、展开折叠区）后重新扫描 |
| 填充全部 | 填充列表里所有勾选的字段 |
| 全选 / 已选 N/M | 列表顶部一次勾选或取消全部字段；「填充全部」只填勾上的 |
| 填充此字段 / 换一个 | 行内图标按钮，鼠标悬停该行时显形；「换一个」重新生成一个值 |
| 撤销 | 底部工具条；恢复到上一次填充前的值（**上传的文件不能撤销**） |
| 清除全部 | 底部工具条；把识别到的字段置空，框架单选组等无法清空的控件会在状态栏如实提示 |
| 跳过 N 个 | 点开可看被跳过的字段与原因（禁用 / 只读 / 自定义上传按钮等），会滚动到对应位置 |

字段行带序号；页面不给标签时显示灰色「未命名」，按序号认位置即可。行上的规则名标签：**蓝色**是识别出的具体规则，**灰色「兜底文本」**表示没有命中关键词、走的是兜底生成——看到灰标签说明这个值可能不合规，可以手动改，也可以去规则中心给它加一条规则；**琥珀色带 ✎** 表示命中了你自定义的规则。上传类字段的值是只读的（文件名由文件池或合成决定）。

长表单会自动边滚边扫，覆盖折叠区和滚动后才懒挂载的字段，填充结束会把页面滚回原位置。

填充结束后会等约半秒，再回读页面自己的校验提示：没有通过页面校验的字段标黄并显示页面原文（支持 Element Plus、Ant Design 及常见错误类名），状态栏汇总数量；扩展自身没填成功的字段仍标红。只统计这次真正写过值的字段，页面原有的红字不会算到这次填充头上。部分表单只在手动失焦后才触发校验，这类提示可能读不到，请以页面实际显示为准。

## 设置

入口是弹窗底部的「⚙ 设置」，在当前弹窗内切换视图，不开新标签页。设置分「填充 / 随机数据 / 上传」三组，开关和输入**改完即存**，保存后旁边会闪一下「✓ 已保存」。

- **填充行为**：默认「只填空白」，可切换「覆盖已有值」。
- **数据标记**：给自己造的数据打归属标记，方便事后在业务系统里搜出来。前缀/后缀加在**规则中心里勾了「贴数据标记」的规则**生成的值两端；出厂默认给「企业名称」与「兜底文本」（`test-xxxxx` 这类）开启，其它规则默认不加。填 `qa-` 后企业名称变成 `qa-宁波星辰科技有限公司`、兜底文本变成 `qa-test-k3j2h`。**不自动补分隔符、也不截短随机部分**，所以值会变长——字段有 `maxlength` 时可能被页面截掉末尾标记。手机号、证件号、日期这类有格式或校验位约束的规则不要勾，加了反而过不了页面校验。
- **随机数据规则**：点「打开规则中心」进入，见下一节。
- **上传文件池**：预置自己的真实文件（单个 ≤ 2MB，最多 10 个），填充上传控件时按 `accept` 优先匹配池里的文件；池为空或没有匹配时才合成 PNG / PDF。
  - **池文件不满足字段门槛时会自动跳过、改用合成文件**：字段提示写了「单张 50KB 以内」而你的图 800KB，或写了「尺寸大小为：480\*480px」而你的图是 1000×800，都不会被注入（否则页面会静默拒收，你只看到红字）。合成图会按提示里的尺寸绘制。
  - 不会裁剪或压缩你的图片。想让某个字段用上真实图片，就预置一张**同时满足该字段体积与尺寸要求**的图。
- **合成图片**：池里没有可用文件时按这里绘制兜底图，可配置文字内容（留空则不写字）、文字位置（九宫格）和默认尺寸（留空为 240×160），右侧小预览实时更新。字段自身声明了尺寸（如 `480*480px`）时仍以字段为准。

## 规则中心

所有随机数据都由这里的规则决定。两个入口：弹窗设置页的「打开规则中心」（窗内切换，「← 返回」回到字段列表），或选项页（`chrome://extensions` → FormFaker 卡片「详情」→「扩展程序选项」）。改完立刻生效——回到字段列表时若规则变过会自动重新识别。

### 内置规则

按七组归类，每条都能看到命中关键词与生成方式，也都可修改。分组默认收起，点分组标题展开想看的那组；搜索时会自动展开命中的分组。

| 分组 | 规则 | 命中关键词（节选） | 生成 |
| --- | --- | --- | --- |
| 联系人与身份 | 手机号 | 手机、移动电话、mobile、cellphone | 真实号段 + 8 位数字 |
| | 固定电话 | 座机、固定电话、传真、电话、tel、fax | 区号-7~8 位 |
| | 电子邮箱 | 邮箱、email、e-mail | 账号池 + 数字 @ 域名池 |
| | 中文姓名 | 姓名、联系人、法定代表人、负责人、收货人、name | 姓氏池 + 1~2 个名字用字 |
| | 性别 | 性别、gender | 男 / 女 |
| | 学历 | 学历、学位、education | 博士 / 硕士 / 本科 / 大专 / 高中 |
| 企业与证照 | 统一社会信用代码 | 信用代码、工商注册号、税号、纳税人、uscc | 18 位，GB 32100 校验位 |
| | 居民身份证号 | 身份证、identity、idcard | 真实地区码 + 出生日期 + GB 11643 校验位 |
| | 银行卡号 | 银行卡、银行账号、开户、账号 | 16~19 位 + Luhn 校验位 |
| | 护照号 | 无关键词，只由「证照类型」联动选中 | E/G/P/EA + 8 位数字 |
| | 企业名称 | 公司、企业名、单位名称、供应商名称、客户名称、company、vendor、supplier | 城市 + 字号 + 行业 + 组织形式 |
| 地址与地理 | 省市地区 | 地区、区域、省市、所在地、region、area、province、city | 真实省/市/区三级 |
| | 详细地址 | 地址、address | 区划 + 街道池 + 门牌号幢室 |
| | 邮政编码 | 邮编、邮政编码、postal、zip | 6 位 |
| | 经纬度 | 经纬度、坐标、longitude、latitude、gps、lng、lat | 联动同表单地址离线推导（禁用框也能写入） |
| 数字 | 金额 | 金额、资本、资金、价格、费用、营业额、收入、利润、amount、price、（元） | 两位小数；资本/营收类走整万元 |
| | 整数 | 数量、人数、件数、年限、工龄、区号、count、qty、（个/台/人/年…） | 年限类 1~30，其余 1~999 |
| 日期 | 日期 | 日期、时间、date、time | `YYYY-MM-DD` / `YYYY-MM-DD HH:mm:ss` |
| 文本 | 网址 | 网址、官网、网站、website、url、link | https 网址 |
| | 段落备注 | 备注、说明、简介、描述、范围、理由、remark、desc | 句子池随机 2~4 句 |
| | 兜底文本 | 无关键词，所有规则都没命中时使用 | `test-` + 5 位小写字母数字 |
| 选项 | 页面选项 | 无关键词，下拉/单选/多选/级联的兜底 | 从页面真实候选里随机挑 |

匹配用 label / placeholder / name / id 等线索拼成的文本逐条试关键词，**首个命中者胜**。两个默认行为值得知道：

- **日期默认只填今天及以后**（上界一年）。有效期 / 到期日这类字段填过去日期常被表单判非法。**成立日期 / 出生日期 / 毕业时间 / 入职日期 / 注册时间这类历史字段不受方向设置影响**，始终生成过去的日期。规则里可把方向改成「今天以前」或「不限方向」。
- **邮箱域名池只收 `@` 后面的部分**（如 `example.com`）。误填完整邮箱（`test@example.com`）会自动只取域名并给琥珀色提示；不是合法域名则回退内置域名池。

### 自定义规则

「新建规则」→ 填名称、命中关键词、选生成方式。关键词支持普通文本与 `/…/` 正则（如 `/order\s*no/`），用逗号、顿号或换行分隔——**空格不能分隔关键词**，因为正则里常带空格。**自定义规则整体优先于内置规则**，同层内关键词越长越具体越先匹配。

六种生成方式：

| 生成方式 | 说明 | 例子 |
| --- | --- | --- |
| 文本模板 | 模板 DSL，见下 | 订单号 = `{n:12}` |
| 候选池 | 从某个词库随机取一项 | 内部评级 = 自建池 A/B/C |
| 数值区间 | 指定上下界与小数位 | 数量 = 1~999 整数 |
| 日期 | 格式 + 方向 + 范围跨度 | 有效期 = `YYYY-MM-DD`，今天及以后 |
| 内置算法 | 校验位号码、姓名、企业名、地区、地址、经纬度、金额、整数、段落 | 身份证 = 地区码 + 出生日期 + GB 11643 |
| 页面选项随机 | 从页面真实候选里挑 | 下拉兜底 |

模板 DSL：

```
字符类  {d}数字  {u}大写  {l}小写  {a}字母  {n}大写字母+数字  {m}小写字母+数字  {x}十六进制  {c}汉字  {s}自定义字符集
数量    {d:8} 固定 8 位；{d:3-6} 3~6 位
取值    {pool:词库id}   {num:1-999}   {num:1-500:2}（保留 2 位小数）
日期    {now}   {now:YYYYMM}   {now-30d:YYYYMMDD}
转义    {{ 与 }} 输出字面大括号
```

例：12 位大写字母加数字的订单号 = `{n:12}`；带前缀的企业编号 = `{pool:companyWord}-{d:3}`；固定值 = 直接写字面量。编辑器里实时给三条样例预览，语法不对、引用的词库不存在、用了 `{s}` 却没填字符集都会红字拦下，**不会存进去**。

内置规则同样可改：改关键词、换生成方式、停用（不再参与匹配），改坏了点「恢复默认」退回出厂态。

### 词库

「词库」页签列出全部内置池——姓氏、名字用字、常用汉字、手机号段、座机区号、邮箱账号、邮箱域名、企业字号、企业行业、企业形式、街道名、段落句子、性别、学历、护照前缀——可整份替换，也能新建自己的池供模板 `{pool:id}` 引用。清空内容即撤销覆盖 / 删除自定义池。

### 规则文件

规则与词库可导出为 JSON，也能导入：**合并**保留本地已有规则，**替换**先清空本地全部改动再写入（会二次确认）。导入时逐条校验形状，坏条目跳过并列出原因，不静默丢配置；版本比当前扩展更高的文件会被拒绝，避免读不懂的字段被悄悄丢掉。适合团队里共享一套造数规则。

## 支持范围与已知边界

- iframe 里的表单暂不识别。
- 虚拟滚动表格（`el-table-v2`、AntD `virtual`）只覆盖已渲染的行。
- 不会自动点击「+ 添加一行」，表格需要几行请先手动加好再识别。
- 弹窗选择型字段（客户编码 / 联行号 / 税收编码 / 所属组织等）在弹窗已有记录里随机挑一条并提交；不会先自动填写查询条件，需要分页或逐级选择的弹窗可能选不到。
- 不做跨步骤 / 跨页面的同一实体一致性，每次填充按当前页面独立生成。
- 经纬度按省级行政中心离线推导（含确定性抖动），不是市 / 区级精度。
- 原生控件与 Element Plus 已做真实浏览器验证；Ant Design 路径主要由单元测试覆盖。
- 不保证通过服务端校验，仅尽量满足常见的前端格式约束。

## 隐私与权限

全部数据在本机生成。扩展不包含任何网络请求，不上传、不抓取、不统计任何页面内容。填充行为与合成图样式存在 `chrome.storage.sync`（跟随 Chrome 账号同步）；规则、词库与上传文件池存在 `chrome.storage.local`，只留在本机。导出的规则 JSON 也只写入你自己选择的目录。

权限说明：

- `<all_urls>`：允许在任意业务表单页按需注入内容脚本。
- `scripting`：注入内容脚本。
- `activeTab`：点击图标时对当前标签页的授权兜底。
- `storage` / `unlimitedStorage`：保存设置、规则与上传文件池（文件池可能超过 `storage.local` 默认 5MB 配额）。

## 开发

```bash
pnpm install
pnpm build        # 构建扩展产物到 dist/
pnpm test         # Vitest + jsdom 单元测试
pnpm preview      # 本地预览 dist（需先 build，含 demo.html）
pnpm dev:pages    # Vite 页面构建监听
pnpm dev:workers  # content / background 构建监听
pnpm region       # 重新生成行政区划数据（依赖更新后执行）
```

技术栈：Manifest V3、TypeScript、Vite 6、React 19（弹窗 / 设置界面）、esbuild（content / background 独立打包）、Vitest + jsdom。扩展不引入 UI 组件库，demo 页单独打包 Element Plus 用于真实组件验证。

项目结构：

```
src/
  core/       扫描、语义推断、生成器、规则 DSL、填充策略
  content/    内容脚本与注入守卫
  background/ Service Worker（按需注入）
  popup/      弹窗界面
  shared/     设置 / 规则中心组件、消息与存储
  dev/        开发期自检 harness 与落地审计
  demo/       自带 demo 页
test/         Vitest + jsdom 单元测试
docs/         产品设计与技术设计文档
.github/      打 tag 触发构建与发布的工作流
```

测试覆盖生成器校验位、语义匹配、控件分类、原生与框架控件填充、表格列头标签、滚动懒挂载、弹窗选择、上传门槛、落地审计与页面校验回读等路径，目前共 18 个测试文件、360+ 用例。

demo 页另带开发期一键自检：注入 `harness.js` 后调用 `window.__ff.selfCheck()`，会跑「扫描 → 生成 → 填充 → 独立期望表审计」并输出违规清单。`harness.js` 只在开发构建中产生，不随发布包分发。

### 发布

发布由 GitHub Actions 自动完成（[`.github/workflows/release.yml`](.github/workflows/release.yml)）。同步 bump `package.json` 与 `public/manifest.json` 的 `version` 后，打 tag 并推送：

```bash
git tag v0.2.0
git push origin v0.2.0
```

工作流会运行 `pnpm test` 与 `pnpm build`，校验 tag、`package.json`、`manifest.json` 三处版本号一致（不一致直接失败），再把 `dist/` 打成 `FormFaker-<版本>.zip`（排除开发自检用的 `harness.js`），连同 `SHA256SUMS.txt` 创建 GitHub Release。

`dist/` 与 `release/` 都不入库。构建产物使用固定文件名（不带内容哈希），方便需要按文件名做脚本白名单的环境；版本追溯依赖 `package.json` 与 `public/manifest.json` 中的 `version`。

## 参与贡献

欢迎在 [GitHub Issues](https://github.com/xuankew/formFaker/issues) 反馈问题，或直接提交 Pull Request：

- 反馈识别错误时，附上字段在页面上的标签、使用的组件库（原生 / Element Plus / Ant Design）和截图会更高效。弹窗红字里的现场清单（`rows= / leaves= / tables=`）是定位弹窗选择问题的关键。
- 新增业务规则通常不需要改代码，直接在规则中心新建并导出 JSON 分享即可。
- 提交代码前请运行 `pnpm test` 与 `pnpm build`。
- 请勿在 Issue、日志或测试数据中提交真实业务数据、账号凭据或内网地址。

设计与实现细节见 [`docs/product-design.md`](docs/product-design.md) 和 [`docs/technical-design.md`](docs/technical-design.md)。
