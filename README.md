# FormFaker 表单造数助手

Chrome 扩展：识别页面上的表单控件，推断中文业务语义（姓名 / 手机号 / 统一社会信用代码 / 注册资本 / 证照类型联动 …），离线生成合规随机数据并填进去。用于测试环境造数，不发任何网络请求。

内置一套可逐条改写的中文业务字段规则（见「规则中心」），也能用模板 DSL 自定义任意格式——比如「订单号 = 12 位大写字母加数字」写成 `{n:12}` 即可。

当前版本：0.1.4（MV3，建议 Chrome 116 及以上）

## 安装

1. 下载 / 解压 `release/FormFaker-0.1.4.zip` 到任意目录（目录不能删，Chrome 是按需读取的）。
2. 打开 `chrome://extensions`，右上角开启「开发者模式」。
3. 点「加载已解压的扩展程序」，选中解压出来的目录（里面有 `manifest.json`）。
4. 建议把扩展图标固定到工具栏，方便随时点开。

> 想直接从源码构建：`pnpm install && pnpm build`，然后加载 `dist/` 目录。

## 升级

1. 把新版 zip 解压到**原来那个目录**，提示覆盖时全部选「替换」（目录路径别变，变了就得重新加载一次）。
2. 打开 `chrome://extensions`，在 FormFaker 卡片上点刷新图标（重新加载）。
3. 刷新已经打开的业务页面——旧页面里跑的还是旧的内容脚本。
4. 卡片上的版本号应该变成新版本号，用它确认升级生效。

设置不用重配：填充行为存在 `chrome.storage.sync`，随机数据规则与上传文件池存在 `chrome.storage.local`，都跟解压目录无关，覆盖文件不会丢。从 0.1.x 升级上来的旧设置（日期格式、邮箱域名、手机号段、企业后缀、名称前后缀）会在首次打开规则中心时自动迁移成对应的规则与词库覆盖，不需要重配。

## 快速上手

1. **先在 demo 页试一遍**：地址栏打开 `chrome-extension://<扩展ID>/demo.html`（ID 在 `chrome://extensions` 的卡片上），点扩展图标 → 「填充全部」。这个页面自带原生控件 + Element Plus 组件 + 联系人子表 + 弹窗选择 + 上传门槛样例，用来确认扩展工作正常。
2. **再到业务页用**：打开要造数的表单页 → 点扩展图标 → 弹窗里会列出识别到的字段（此时**只识别、不会自动填**）→ 检查一遍 → 点「填充全部」。

## 弹窗里的操作

| 操作 | 说明 |
| --- | --- |
| 重新识别 | 页面结构变化（切换步骤、展开折叠区）后重新扫描 |
| 填充全部 | 填充列表里所有字段 |
| 填充此字段 / 换一个 | 行内图标按钮，鼠标悬停该行才显形；「换一个」重新生成一个值 |
| 撤销 | 恢复到上一次填充前的值（**上传的文件不能撤销**） |
| 清除全部 | 把识别到的字段置空；红色按钮，框架单选组等无法清空的控件会在状态栏如实提示 |
| 跳过 N 个 | 点开可看被跳过的字段与原因（禁用 / 只读 / 自定义上传按钮等），会滚动到对应位置 |

字段行上的标签显示命中的规则名：**蓝色**是识别出的具体规则，**灰色「兜底文本」**表示没命中任何关键词、走的是兜底生成——看到灰标签就说明这个字段的值可能不合规，可以手改，也可以去规则中心给它加一条规则；**琥珀色带 ✎** 表示命中的是你自己新建的规则。上传类字段的值是只读的（文件名由文件池或合成决定）。

长表单会自动边滚边扫（覆盖折叠区、滚动后才懒挂载的字段），填充结束会把页面滚回原位置。

## 设置（弹窗底部「⚙ 设置」，窗内切换，不开新标签页）

- **填充行为**：默认「只填空白」，可切「覆盖已有值」。
- **名称标记**：给自己造的数据打归属标记，方便事后在业务系统里搜出来。填 `qa` 后，名称类文本变成 `qatest-k3j2h`、企业名称变成 `qa宁波星辰科技有限公司`；想要分隔符就自己写进去（`qa-`）。**不自动补分隔符、也不截短随机部分**，所以值会变长——字段有 `maxlength` 时可能被页面截掉末尾标记。只作用于「企业名称」与「兜底文本」这两类名称字段，人名、手机号、邮箱、地址、证照号等仍按各自规则生成（加了标记反而过不了格式校验）。
- **上传文件池**：预置自己的真实文件（单个 ≤2MB，最多 10 个），填充上传控件时按 `accept` 优先匹配池里的文件，池为空或没有匹配才合成 PNG/PDF。
  - **池文件不满足字段门槛时会自动跳过、改用合成文件**：字段提示写了「单张 50KB 以内」而你的图 800KB，或写了「尺寸大小为：480\*480px」而你的图是 1000×800，都不会被注入（否则页面会静默拒收，你只看到红字）。合成图会按提示里的尺寸画。
  - 不会裁剪或压缩你的图片。想让某个字段用上真实图片，就预置一张**同时满足该字段体积与尺寸要求**的图。
- **随机数据规则**：点「打开规则中心」进入，见下一节。

## 规则中心

所有随机数据都由这里的规则决定。入口两个：弹窗设置页的「打开规则中心」（窗内切换，「← 返回」回字段列表），或选项页（`chrome://extensions` → FormFaker 卡片「详情」→「扩展程序选项」，两块设置直接铺开）。改完立刻生效——回到字段列表时若规则变过会自动重新识别。

### 内置规则

按七组归类，每条都能看到命中关键词与生成方式，也都可改：

| 分组 | 规则 | 命中关键词（节选） | 生成 |
| --- | --- | --- | --- |
| 联系人与身份 | 手机号 | 手机、移动电话、mobile、cellphone | 真实号段 + 8 位数字 |
| | 固定电话 | 座机、固定电话、传真、电话、tel、fax | 区号-7~8 位 |
| | 电子邮箱 | 邮箱、email、e-mail | 账号池 + 数字 @ 域名池 |
| | 中文姓名 | 姓名、联系人、法定代表人、负责人、收货人、name | 姓氏池 + 1~2 个名字用字 |
| | 性别 | 性别、gender | 男 / 女 |
| | 学历 | 学历、学位、education | 博士 / 硕士 / 本科 / 大专 / 高中 |
| 企业与证照 | 统一社会信用代码 | 信用代码、工商注册号、税号、纳税人、uscc | 18 位，GB 32100 校验位 |
| | 居民身份证号 | 身份证、identity、idcard | 真实地区码 + 出生日期 + GB 11643 校验位 |
| | 银行卡号 | 银行卡、银行账号、开户、账号 | 16~19 位 + Luhn 校验位 |
| | 护照号 | 无关键词，只由「证照类型」联动选中 | E/G/P/EA + 8 位数字 |
| | 企业名称 | 公司、企业名、单位名称、供应商名称、客户名称、company、vendor、supplier | 城市 + 字号 + 行业 + 组织形式 |
| 地址与地理 | 省市地区 | 地区、区域、省市、所在地、region、area、province、city | 真实省/市/区三级 |
| | 详细地址 | 地址、address | 区划 + 街道池 + 门牌号幢室 |
| | 邮政编码 | 邮编、邮政编码、postal、zip | 6 位 |
| | 经纬度 | 经纬度、坐标、longitude、latitude、gps、lng、lat | 联动同表单地址离线推导（禁用框也能写入） |
| 数字 | 金额 | 金额、资本、资金、价格、费用、营业额、收入、利润、amount、price、（元） | 两位小数；资本/营收类走整万元 |
| | 整数 | 数量、人数、件数、年限、工龄、区号、count、qty、（个/台/人/年…） | 年限类 1~30，其余 1~999 |
| 日期 | 日期 | 日期、时间、date、time | `YYYY-MM-DD` / `YYYY-MM-DD HH:mm:ss` |
| 文本 | 网址 | 网址、官网、网站、website、url、link | https 网址 |
| | 段落备注 | 备注、说明、简介、描述、范围、理由、remark、desc | 句子池随机 2~4 句 |
| | 兜底文本 | 无关键词，所有规则都没命中时用 | `test-` + 5 位小写字母数字 |
| 选项 | 页面选项 | 无关键词，下拉/单选/多选/级联的兜底 | 从页面真实候选里随机挑 |

匹配用 label / placeholder / name / id 拼成的文本逐条试关键词，**首个命中者胜**。两个默认行为值得知道：

- **日期默认只填今天及以后**（上界一年）。有效期 / 到期日这类字段填过去的日期常被表单判非法。**成立日期 / 出生日期 / 毕业时间 / 入职日期 / 注册时间这类历史字段不受方向设置影响**，始终生成过去的日期——否则会出现「出生日期 2027 年」这种数据。规则里可把方向改成「今天以前」或「不限方向」。
- **邮箱域名池只收 `@` 后面的部分**（如 `example.com`）。误填完整邮箱（`test@example.com`）会自动只取域名并给琥珀色提示；填的不是合法域名则回退内置域名池。

### 自定义规则

「新建规则」→ 填名称、命中关键词、选生成方式。关键词支持普通文本与 `/…/` 正则（如 `/order\s*no/`），用逗号、顿号或换行分隔——**不要指望空格能分开关键词**，正则里常带空格。**自定义规则整体优先于内置规则**，同层内关键词越长越具体越先匹配。

六种生成方式：

| 生成方式 | 说明 | 例子 |
| --- | --- | --- |
| 文本模板 | 模板 DSL，见下 | 订单号 = `{n:12}` |
| 候选池 | 从某个词库随机取一项 | 内部评级 = 自建池 A/B/C |
| 数值区间 | 指定上下界与小数位 | 数量 = 1~999 整数 |
| 日期 | 格式 + 方向 + 范围跨度 | 有效期 = `YYYY-MM-DD`，今天及以后 |
| 内置算法 | 校验位号码、姓名、企业名、地区、地址、经纬度、金额、整数、段落 | 身份证 = 地区码 + 出生日期 + GB 11643 |
| 页面选项随机 | 从页面真实候选里挑 | 下拉兜底 |

模板 DSL：

```
字符类  {d}数字  {u}大写  {l}小写  {a}字母  {n}大写字母+数字  {m}小写字母+数字  {x}十六进制  {c}汉字  {s}自定义字符集
数量    {d:8} 固定 8 位；{d:3-6} 3~6 位
取值    {pool:词库id}   {num:1-999}   {num:1-500:2}（保留 2 位小数）
日期    {now}   {now:YYYYMM}   {now-30d:YYYYMMDD}
转义    {{ 与 }} 输出字面大括号
```

例：12 位大写字母加数字的订单号 = `{n:12}`；带前缀的企业编号 = `{pool:companyWord}-{d:3}`；固定值 = 直接写字面量。编辑器里实时给三条样例预览，语法不对、引用的词库不存在、用了 `{s}` 却没填字符集都会红字拦下、**不会存进去**。

内置规则同样可改：改关键词、换生成方式、停用（不再参与匹配），改坏了点「恢复默认」退回出厂态。

### 词库

「词库」页签列出全部内置池——姓氏、名字用字、常用汉字、手机号段、座机区号、邮箱账号、邮箱域名、企业字号、企业行业、企业形式、街道名、段落句子、性别、学历、护照前缀——可整份替换，也能新建自己的池供模板 `{pool:id}` 引用。清空内容即撤销覆盖 / 删除自定义池。

### 规则文件

规则与词库可导出为 JSON，也能导入：**合并**保留本地已有规则，**替换**先清空本地全部改动再写入（会二次确认）。导入时逐条校验形状，坏条目跳过并列出原因，不静默丢配置；版本比当前扩展更高的文件会被拒，避免读不懂的字段被悄悄丢掉。适合团队里共享一套造数规则。

## 常见问题

**点图标后红字「无法在浏览器内部页面运行」** — `chrome://`、扩展商店、`about:` 这类页面 Chrome 不允许注入脚本，切到普通 http/https 页面再用。

**红字「当前页面未能注入脚本，请刷新本页后点重新识别」** — 通常是扩展刚重载过或页面是注入前打开的。扩展会自动重注入并重试一次，仍失败才提示；按提示刷新页面即可（括号里保留的是 Chrome 的原始错误，便于排查）。

**上传字段红字「上传被页面拒绝 … msg=图片格式不正确」** — `msg=` 后面是页面自己的原话，按它处理：说格式就往文件池放对应格式的文件；说尺寸就看字段提示有没有写尺寸（写了我们会照做，没写就无从推断）。

**弹窗选择型字段（客户编码 / 联行号 / 税收编码 / 所属组织这类）报错** — 这类字段的候选是业务主数据，本地伪造不出来，扩展会打开弹窗**随机挑一条记录**并提交（树形弹窗只在叶子里随机，组织组这类父节点不会被选中；一个叶子都没有时先点一次「展开」再挑）。若弹窗需要先填查询条件才有记录，会红字提示「弹窗内没有可选记录」并附现场清单（行数 / 叶子数 / 表数 / 点过哪些控件），把红字截图反馈即可定位。

**某个字段识别错了 / 压根没识别出来** — 去规则中心处理：识别错了就改那条规则的关键词，或把它停用（停用后不再参与匹配，字段会落到兜底）；没识别出来就「新建规则」，把该字段在页面上的标签文字写进关键词。自定义规则整体优先于内置规则，不用担心被内置的抢走。

**表格里只填了已有的行** — 不会自动点「+ 添加一行」，需要几行请先手动加好再识别。

## 已知边界

- iframe 里的表单暂不识别。
- 虚拟滚动表格（`el-table-v2`、AntD `virtual`）只覆盖已渲染的行。
- Element Plus 与原生控件经过真实浏览器验证，Ant Design 路径只有单测覆盖。
- 经纬度按省级行政中心离线推导（含确定性抖动），不是市/区级精度。

## 隐私

全部数据在本机生成，扩展不含任何网络请求，也不上报任何内容。「覆盖已有值」这一个开关存在 `chrome.storage.sync`（跟随你的 Chrome 账号同步）；规则、词库与文件池存在 `chrome.storage.local`，只留在本机。导出的规则 JSON 也只落到你自己选的目录。

权限说明：`<all_urls>` 主机权限是为了能在任意业务表单页按需注入脚本（不依赖点击手势的授权时机）；`unlimitedStorage` 是为了让文件池突破 `storage.local` 默认 5MB 配额；`scripting` 用于注入；`activeTab` 是点击图标时对当前标签页的授权兜底。

## 开发

```bash
pnpm install
pnpm build        # 产出 dist/
pnpm test         # vitest
pnpm preview      # 本地预览 dist（含 demo.html）
```

打包发布：

```bash
pnpm build
cd dist && zip -qr ../release/FormFaker-0.1.4.zip . -x harness.js
cd dist && shasum -a 256 background.js content.js assets/*.js > ../release/SHA256SUMS.txt
```

`harness.js` 是开发期的自检工具（`window.__ff.selfCheck()`），不随包发布。`dist/` 与 `release/` 都不入库。

构建产物**文件名固定、不带内容哈希**，所以每次构建的文件名都一样，只有 `SHA256SUMS.txt` 里的哈希会随代码变化；也因此**从文件名看不出是哪次构建**：发版前记得手动 bump `public/manifest.json` 与 `package.json` 的 `version`（扩展卡片上显示的就是它）。固定文件名也让内网 / 企业环境可以按文件名给脚本加加载白名单，升级后不必重新报备。扩展不含远程脚本、`eval` 或动态注入的 JS，`manifest.json` 与 HTML 里没有内联 `<script>`。

设计与实现细节见 `docs/product-design.md`、`docs/technical-design.md`。
