# FormFaker 表单造数助手 — 产品设计文档

- 版本：v0.1（MVP 设计）
- 日期：2026-09-14
- 形态：Chrome 扩展（Manifest V3）

## 1. 背景与目标

企业系统（SRM 供应商准入、OA 审批、CRM 建档等）存在大量长表单，手工填写测试数据耗时且易错。
典型页面如「供应商准入申请」：5 个步骤、数十个字段，混合了下拉、日期、级联地区、上传、多选等控件。

FormFaker 的目标：**一键识别页面表单控件的「类型 + 业务含义」，自动生成合规的随机测试数据并填入表单**，
把一次长表单的造数时间从 5~10 分钟压缩到 10 秒内。

### 1.1 目标用户

- 功能测试 / QA：回归测试反复造数。
- 前端开发：联调、自测时快速铺数据。
- 实施 / 售前：演示环境快速录入样例数据。

### 1.2 设计原则

1. **零侵入**：不修改页面代码、不常驻页面脚本，用户不点击就零开销。
2. **像真人一样填**：填充走「真实事件」路径（原生 setter + 事件、真实 click），兼容 React / Vue 受控组件与 Element / Ant Design 等组件库。
3. **数据要「真」**：手机号符合号段、身份证/统一社会信用代码过校验位、地区是真实行政区划，避免被前端校验拦下。
4. **可预览可反悔**：填充前可在面板里看、改、换；填充后可一键撤销（恢复填充前快照）或一键清除（把识别到的字段全部置空）。
5. **可扩展**：控件类型、语义关键词、生成器均为注册表式插件结构，新增类型不改主流程。

## 2. 产品形态与核心流程

```
┌─ Chrome 工具栏图标 ──点击──► 注入 content script（按需） + 打开 Popup 弹窗
│
└─ Popup 弹窗（主操作界面）
     ① 识别：扫描当前 tab 的可见表单控件 → 字段列表（打开弹窗即识别，但绝不自动填充）
     ② 预览：每行 = 标签 | 控件类型 | 语义 | 生成的值（可编辑）
     ③ 调整：单字段重roll / 排除 / 手改值
     ④ 填充：点「填充全部」或单条「→」才写入页面（默认不自动填充）
     ⑤ 清除：点「清除全部」把识别到的字段一键置空
     ⑥ 撤销：恢复填充前的快照
```

交互细节：

- 入口仅一个：工具栏图标（点击后自动弹出 Popup）。不向页面注入悬浮按钮，避免污染被测页面。
- 主界面采用 **Popup 弹窗**（用户指定形态）。权衡：Popup 点外部即关闭，无法「边看页面边调数据」；但填充/撤销/清除的真实状态保存在 content script 内存中，关弹窗不丢失，重开弹窗会重新识别（成本低），故可接受。早期曾评估 Side Panel（常驻不关），因用户偏好 Popup 而弃用。
- 识别结果以「字段」为单位展示；灰置（disabled）、只读、隐藏控件自动跳过并可在面板中查看跳过原因（折叠区）。**例外**：标签命中「经纬度/坐标」的控件即便被禁用/只读也视为可填——这类字段通常由地图选点回填、设计上即为禁用，需联动地址生成坐标后写入。
- 对「选项驱动」控件（下拉/单选/多选/级联），若无语义命中，值显示为 `(填充时随机选择)`，填充时从真实展开的选项里随机挑；用户也可手输选项文本强制指定。

## 3. 控件类型 × 语义 × 生成 × 填充 矩阵

> 「识别信号」= 如何判定控件类型；「语义」= 如何理解业务含义；MVP 覆盖下表全部行。

| # | 控件类型 | 识别信号（DOM） | 语义示例（关键词） | 生成策略 | 填充策略 |
|---|---------|----------------|------------------|---------|---------|
| 1 | 单行文本 | `input[type=text/无]` | 姓名/公司/备注… | 按语义生成器 | 原生 setter + `input`/`change` |
| 2 | 手机号文本框 | 同上 + 语义命中 | 手机、移动电话、mobile、联系电话 | 合规号段 11 位 | 同 1 |
| 3 | 座机号文本框 | 同上 | 座机、固定电话、传真、tel | 区号-7/8 位 | 同 1 |
| 4 | 多行文本 | `textarea` | 备注、说明、简介、经营范围 | 2~4 句中文段落 | 同 1 |
| 5 | 数字/金额 | `input[type=number]`、`.el-input-number`、`.ant-input-number` | 注册资本、金额、价格、数量 | 金额两位小数 / 数量整数 | 同 1 |
| 6 | 原生下拉 | `select` | 纳税类别、企业性质… | 选项匹配语义，否则随机选项 | 设 value + `change` |
| 7 | 组件库下拉 | `.el-select`、`.ant-select`、`[role=combobox]` | 同 6 | 同 6（选项在展开后读取） | 点击触发→等面板→点选项 |
| 8 | 多选（组件库/原生） | `.ant-select-multiple`、`select[multiple]`、checkbox 组 | 经营范围、资质 | 随机 1~3 项 | 逐项点击 / 多选 selected |
| 9 | 级联选择（行政区划） | `.el-cascader`、`.ant-cascader` | 注册地区、所在省市 | 真实省/市/区三级路径 | 逐级展开点击匹配文本 |
| 10 | 日期 | `.el-date-editor`、`.ant-picker`、`input[type=date]` | 成立日期、有效期起 | 随机合理日期 `YYYY-MM-DD` | 内层 input 键入 + Enter/blur |
| 11 | 日期时间 | 带 time 变体 | 创建时间 | `YYYY-MM-DD HH:mm:ss` | 同 10 |
| 12 | 日期范围 | `.ant-picker-range`、`--daterange` | 有效期 | 起 < 止 一对 | 两个内层 input 依次键入 |
| 13 | 单选组 | `input[type=radio]` 同名分组、`.el-radio-group` | 性别、是否 | 选项匹配或随机 | 点击目标 label |
| 14 | 复选框（单） | `input[type=checkbox]` 独立 | 同意协议、是否一般纳税人 | 随机布尔 | 按期望态点击 |
| 15 | 开关 | `.el-switch`、`.ant-switch` | 启用状态 | 随机布尔 | click |
| 16 | 上传图片 | `.el-upload`/`.ant-upload` + accept=image、`input[type=file][accept^=image]` | 营业执照、logo | 文件池优先匹配，回退本地 canvas 生成 PNG | DataTransfer 注入 files + `change` |
| 17 | 上传文件 | 同上 accept 非 image | 附件、章程 | 文件池优先匹配，回退本地生成最小合法 PDF | 同 16 |
| 18 | 富文本 | `[contenteditable=true]`、`.ql-editor`、`.w-e-text` | 企业简介 | HTML 段落 | 写 innerHTML + `input` |
| 19 | 邮箱/网址/密码框 | `input[type=email/url/password]` | 邮箱、官网 | 对应格式 | 同 1 |
| 20 | 地址文本框 | 语义命中「地址」 | 注册地址、通讯地址 | 真实区划 + 路名门牌 | 同 1 |
| 21 | 经纬度文本框 | 语义命中「经纬度/坐标」（常为 disabled） | 经纬度、坐标、GPS | 联动同表单地址生成对应坐标 | 同 1（禁用框亦可程序化写入） |

补充说明：

- **身份证、银行卡、信用代码**等语义即使落在普通文本框上也会生成带校验位的合规值（前端校验可通过）。
- 识别不到语义的文本框 → 生成中性测试串（如 `autotest-8f3k2`），保证「能填」优先于「填得像」。
- 表格内可编辑单元格、动态增减行（如「联系人列表」+ 新增按钮）：MVP 只识别当前已渲染的行；「自动点新增行再填」列入 V1.1。

优先级规则：更具体的在前（如「手机」先于「电话」；「信用代码」先于「账号」；「邮箱」先于「地址」）。
词典与生成器均为注册表。设置面板（`SettingsPanel`，Popup 内嵌设置视图 + 选项页共用）已内置「随机数据规则」编辑器：内置一套默认规则，用户自定义项优先级更高（当前覆盖日期/日期时间格式、邮箱域名、手机号段、企业后缀；留空即回退内置）。更细粒度的语义规则/生成器 JSON 编辑器列入 V1.1。

## 5. 功能清单

### MVP（本次实施）

1. 按需注入 + Popup 弹窗主界面（识别 / 预览 / 编辑 / 重roll / 排除 / 单条与全量填充 / 清除全部 / 撤销 / 设置）。设置以窗内视图切换（设置 / ← 返回），不再开新标签页。打开弹窗只识别、绝不自动填充；填充与清除均需显式点击按钮。
2. 上表 1~21 全部控件类型的识别与填充（Element Plus / Ant Design / 原生 / ARIA role 四层选择器）。
3. 中文合规数据生成：姓名、手机、座机、邮箱、身份证（校验位）、信用代码（校验位）、护照、银行卡（Luhn）、真实三级行政区划、地址、经纬度坐标（离线按省市质心推导，无网络请求）、公司名、日期/日期时间/范围、金额/数量、段落、URL、邮编、PNG/PDF 文件。
4. 覆盖模式开关：默认「只填空白」，可切换「覆盖已有值」。
5. 撤销：恢复最近一次填充前的值快照。
6. 一键清除：把识别到的字段全部置空——原生控件可靠清空；EP/AntD 下拉/级联/日期经「清除图标」清空（先聚焦/悬停揭示 × 再点击）；框架单选组无「取消选择」能力，计入「无法清空」并在状态栏提示。
7. 自定义随机数据规则 + 上传文件池（共享设置面板 `SettingsPanel`，在 Popup 内嵌设置视图与独立选项页共用）：规则为内置默认 + 用户覆盖（日期/日期时间格式、邮箱域名、手机号段、企业后缀），经 chrome.storage.sync 持久化，Popup 订阅 storage.onChanged 实时生效；文件池允许预设本地上传文件（单个 ≤2MB、最多 10 个）存入 chrome.storage.local（需 unlimitedStorage 权限），填充上传控件时按 accept 优先匹配真实文件，无匹配再回退合成 PNG/PDF。
8. 跨字段联动：证照/证件号码跟随证照/证件类型的当前选择生成对应格式（统一社会信用代码→18 位信用代码、居民身份证→18 位身份证、护照→护照号、其他→通用串）；经纬度跟随**同一表单内**的地址/地区字段生成对应坐标（按表单作用域配对，多表单页不会错链；地址或坐标任一方重roll 时另一方同步）；「注册资本/实缴资金（单位:元）」类字段按整数元生成以通过金额校验。
9. demo 页（原生 + Element Plus 真实组件，含「注册地址 + 禁用经纬度」联动样例）+ 单元测试（生成器校验位与自定义规则、语义推断、证照联动、经纬度联动与禁用白名单、控件分类、原生填充与清除）。

### V1.1+ 路线（不在本次范围）

- 语义规则/生成器的 JSON 级编辑器（在已落地的结构化「随机数据规则」之上，进一步开放语义关键词与生成器的自由扩展）。
- 动态行：自动点击「新增」按钮后识别填充。
- iframe 内表单（all_frames）。
- 站点级记忆：记住某 URL 的排除项与手改值。
- 填充历史与多套数据方案切换；i18n（en-US 数据池）。
- 键盘快捷键、批量多 tab 填充。

## 6. 非功能需求

| 维度 | 指标 |
|------|------|
| 空闲开销 | 0：无常驻 content script，无 MutationObserver 常驻 |
| 识别耗时 | 500 控件页面 ≤ 300ms（单次遍历 + 索引化 label 查找） |
| 填充体验 | 原生控件批量同步填充不阻塞主线程（分片 rAF）；组件库控件逐个异步（需等下拉展开） |
| 内存 | 字段列表与元素引用仅在弹窗会话期持有，重扫/关弹窗即释放 |
| 隐私 | 全部本地生成，无任何网络请求；权限 scripting/storage/activeTab + host_permissions `<all_urls>`（仅为按需注入任意业务页，不发起网络请求） |
| 兼容 | Chrome 116+；React 18/19、Vue 3、Element Plus、Ant Design 4/5、原生表单 |

## 7. 非目标

- 不自动提交表单、不绕过验证码、不抓取线上真实数据。
- 不做 Firefox/Safari 适配（MV3 API 以 Chrome 为准）。
- 不做「保证通过服务端校验」的承诺（仅保证常见前端格式校验可通过）。

## 8. MVP 验收标准

1. demo 页（原生区 + Element Plus 区）打开弹窗即识别，但**绝不自动填充**；点「填充全部」后所有控件值为合规随机数据，Vue/React 状态同步（提交可取到值）。
2. 截图同类页面（SRM 准入表单风格）人工验证：识别覆盖率 ≥ 90% 可见控件，误填率 0（disabled/只读不被填）。
3. 填充后点「撤销」，页面恢复填充前状态（上传项除外，文档中明示）。
4. 填充后点「清除全部」，识别到的字段全部置空；框架单选组等不支持清空的控件在状态栏计入「无法清空」并如实提示。
5. 在 Popup 设置页（点「设置」进入窗内视图，「← 返回」回到字段列表；选项页为兜底入口）自定义日期格式/邮箱域名/手机号段/企业后缀并保存后，重新识别生成的数据遵循自定义规则；用户规则优先级高于内置默认，留空则回退默认。同一设置页可维护上传文件池，加入文件后填充上传控件应优先注入按 accept 匹配的真实文件，池为空或无匹配时回退合成 PNG/PDF。
6. `pnpm build` 通过、`pnpm test` 全绿；加载 dist 无 console error。
