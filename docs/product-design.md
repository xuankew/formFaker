# FormFaker 表单造数助手 — 产品设计文档

- 版本：v0.1（MVP 设计）
- 日期：2026-09-14
- 形态：Chrome 扩展（Manifest V3）

## 1. 背景与目标

企业系统（供应商准入、OA 审批、CRM 建档等）存在大量长表单，手工填写测试数据耗时且易错。
典型页面如「供应商准入申请」：5 个步骤、数十个字段，混合了下拉、日期、级联地区、上传、多选等控件。

FormFaker 的目标：**一键识别页面表单控件的「类型 + 业务含义」，自动生成合规的随机测试数据并填入表单**，
把一次长表单的造数时间从 5~10 分钟压缩到 10 秒内。

### 1.1 目标用户

- 功能测试 / QA：回归测试反复造数。
- 前端开发：联调、自测时快速铺数据。
- 实施 / 售前：演示环境快速录入样例数据。

### 1.2 设计原则

1. **零侵入**：不修改页面代码、不常驻页面脚本，用户不点击就零开销。
2. **像真人一样填**：填充走「真实事件」路径（原生 setter + 事件、真实 click），兼容 React / Vue 受控组件与 Element / Ant Design 等组件库。
3. **数据要「真」**：手机号符合号段、身份证/统一社会信用代码过校验位、地区是真实行政区划，避免被前端校验拦下。
4. **可预览可反悔**：填充前可在面板里看、改、换；填充后可一键撤销（恢复填充前快照）或一键清除（把识别到的字段全部置空）。
5. **可扩展**：控件类型与填充策略是注册表式插件结构，新增类型不改主流程；语义关键词与生成规则是**声明式数据**，用户在规则中心就能改，不必改代码。

## 2. 产品形态与核心流程

```
┌─ Chrome 工具栏图标 ──点击──► 注入 content script（按需） + 打开 Popup 弹窗
│
└─ Popup 弹窗（主操作界面）
     ① 识别：扫描当前 tab 的可见表单控件 → 字段列表（打开弹窗即识别，但绝不自动填充）
     ② 预览：每行 = 标签 | 控件类型 | 语义 | 生成的值（可编辑）
     ③ 调整：单字段重roll / 排除 / 手改值
     ④ 填充：点「填充全部」或单条「→」才写入页面（默认不自动填充）
     ⑤ 清除：点「清除全部」把识别到的字段一键置空
     ⑥ 撤销：恢复填充前的快照
```

交互细节：

- 入口仅一个：工具栏图标（点击后自动弹出 Popup）。不向页面注入悬浮按钮，避免污染被测页面。
- 主界面采用 **Popup 弹窗**（用户指定形态）。权衡：Popup 点外部即关闭，无法「边看页面边调数据」；但填充/撤销/清除的真实状态保存在 content script 内存中，关弹窗不丢失，重开弹窗会重新识别（成本低），故可接受。早期曾评估 Side Panel（常驻不关），因用户偏好 Popup 而弃用。
- 识别结果以「字段」为单位展示；灰置（disabled）、只读、隐藏控件自动跳过并可在面板中查看跳过原因（折叠区）。**例外**：标签命中「经纬度/坐标」的控件即便被禁用/只读也视为可填——这类字段通常由地图选点回填、设计上即为禁用，需联动地址生成坐标后写入。
- 对「选项驱动」控件（下拉/单选/多选/级联），若无语义命中，值显示为 `(填充时随机选择)`，填充时从真实展开的选项里随机挑；用户也可手输选项文本强制指定。
- **当前标签页用不了时要说人话**：在浏览器内部页（chrome://、扩展页、空白页、应用商店）点图标，状态栏直接说明「无法在××运行，请切到普通网页」；普通业务页若脚本没就绪，提示「请刷新本页后重试」并把原始错误附在括号里留证——不把 Chrome 的英文 `Could not establish connection…` 甩给用户。**扩展重新加载后无需刷新业务页**：重注入会自动识别页面里残留的陈旧标记并重新挂载。

## 3. 控件类型 × 语义 × 生成 × 填充 矩阵

> 「识别信号」= 如何判定控件类型；「语义」= 如何理解业务含义；MVP 覆盖下表全部行。

| # | 控件类型 | 识别信号（DOM） | 语义示例（关键词） | 生成策略 | 填充策略 |
|---|---------|----------------|------------------|---------|---------|
| 1 | 单行文本 | `input[type=text/无]` | 姓名/公司/备注… | 按语义生成器 | 原生 setter + `input`/`change` |
| 2 | 手机号文本框 | 同上 + 语义命中 | 手机、移动电话、mobile、联系电话 | 合规号段 11 位 | 同 1 |
| 3 | 座机号文本框 | 同上 | 座机、固定电话、传真、tel | 区号-7/8 位 | 同 1 |
| 4 | 多行文本 | `textarea` | 备注、说明、简介、经营范围 | 2~4 句中文段落 | 同 1 |
| 5 | 数字/金额 | `input[type=number]`、`.el-input-number`、`.ant-input-number` | 注册资本、金额、价格、数量 | 金额两位小数 / 数量整数 | 同 1 |
| 6 | 原生下拉 | `select` | 纳税类别、企业性质… | 选项匹配语义，否则随机选项 | 设 value + `change` |
| 7 | 组件库下拉 | `.el-select`、`.ant-select`、`[role=combobox]` | 同 6 | 同 6（选项在展开后读取） | 点击触发→等面板→点选项 |
| 8 | 多选（组件库/原生） | `.ant-select-multiple`、`select[multiple]`、checkbox 组 | 经营范围、资质 | 随机 1~3 项 | 逐项点击 / 多选 selected |
| 9 | 级联选择（行政区划） | `.el-cascader`、`.ant-cascader` | 注册地区、所在省市 | 真实省/市/区三级路径 | 逐级展开点击匹配文本 |
| 10 | 日期 | `.el-date-editor`、`.ant-picker`、`input[type=date]` | 成立日期、有效期起 | 随机合理日期 `YYYY-MM-DD` | 内层 input 键入 + Enter/blur |
| 11 | 日期时间 | 带 time 变体 | 创建时间 | `YYYY-MM-DD HH:mm:ss` | 同 10 |
| 12 | 日期范围 | `.ant-picker-range`、`--daterange` | 有效期 | 起 < 止 一对 | 两个内层 input 依次键入 |
| 13 | 单选组 | `input[type=radio]` 同名分组、`.el-radio-group` | 性别、是否 | 选项匹配或随机 | 点击目标 label |
| 14 | 复选框（单） | `input[type=checkbox]` 独立 | 同意协议、是否一般纳税人 | 随机布尔 | 按期望态点击 |
| 15 | 开关 | `.el-switch`、`.ant-switch` | 启用状态 | 随机布尔 | click |
| 16 | 上传图片 | `.el-upload`/`.ant-upload` + accept=image、`input[type=file][accept^=image]`（含 `display:none` 的裸 file input）；**无 `accept` 但字段提示含图片线索**（图片/照片/jpg/png…或「尺寸大小为：宽*高」）也归此类——真实页常把限制写在代码里而不写进 accept | 营业执照、logo、商品主图 | **设置页预置的文件池优先，但要先过字段门槛**：体积超过「50KB以内」这类声明、或图片真实像素与「尺寸大小为：480*480px」不符的池文件直接跳过；无可池文件才合成——字段提示写明尺寸时按该尺寸画 PNG，否则 240×160 | DataTransfer 注入 files + `change`；页面拒收（格式/尺寸门槛）时把页面提示原话写进面板红字 |
| 17 | 上传文件 | 同上但 accept 非 image 且提示无图片线索（提示里写 pdf 的字段不会被误判成图片） | 附件、章程 | 文件池优先匹配（同样先过体积门槛），回退本地生成最小合法 PDF | 同 16 |
| 18 | 富文本 | `[contenteditable=true]`、`.ql-editor`、`.w-e-text` | 企业简介 | HTML 段落 | 写 innerHTML + `input` |
| 19 | 邮箱/网址/密码框 | `input[type=email/url/password]` | 邮箱、官网 | 对应格式 | 同 1 |
| 20 | 地址文本框 | 语义命中「地址」 | 注册地址、通讯地址 | 真实区划 + 路名门牌 | 同 1 |
| 21 | 经纬度文本框 | 语义命中「经纬度/坐标」（常为 disabled） | 经纬度、坐标、GPS | 联动同表单地址生成对应坐标 | 同 1（禁用框亦可程序化写入） |
| 22 | 弹窗选择型输入框 | `input[readonly]` + 放大镜/「选择」按钮（`.el-input__suffix .el-icon`、`.el-input-group__append button`、`.ant-input-suffix .anticon` 等）；表格型与**树型**（`[role="treeitem"]`、`.ant-tree-treenode`） | 客户编码、联行号、开户行、税收编码、所属组织 | 占位标记「(填充时随机选择)」——候选是业务主数据，本地无从伪造 | 点触发器开弹窗 → 枚举记录并**随机挑一条**（树形弹窗只在**叶子**里随机，组织组这类父节点不会被选中；一个叶子都没有时先点一次「展开」再挑，仍没有就退回全部记录）→ 按**有序候选链**依次尝试提交（行内 `操作` 列「选择」链接 → 固定列克隆表的同序号行 → 页脚「确定」，每个候选再试其内层节点；只有页脚确定时先点一次记录行以完成高亮选中）→ 校验回填 → 关闭弹窗；框架未回填时读回该记录文本写入，**被还原就再写一次**；**弹窗自关而字段仍为空也算失败**，红字报错并附现场清单（行数/叶子数/表数/点过的控件/读到的记录），用户截图即可定位 |

补充说明：

- **身份证、银行卡、信用代码**等语义即使落在普通文本框上也会生成带校验位的合规值（前端校验可通过）。
- 识别不到语义的文本框 → 生成中性测试串（如 `test-8f3k2`），保证「能填」优先于「填得像」。
- **选项类控件只能落到页面上真实存在的候选项**：命中关键词但生成器产出的是自由文本（模板、段落、区划、带校验位的号码……）时，改走「随机选项」而不是把伪造值填进去——否则下拉面板里根本没有这一项，看着填成功实际是空的。唯一例外是级联选择：地区生成器输出的「省/市/区」正是它的节点文案，对得上。
- **表格内可编辑单元格**（如联系人列表的 姓名/手机号/电子邮箱、银行账户表的 银行账号）：以**列头**作为字段标签（支持 `colspan` 多级表头、ARIA 网格、Element Plus/Ant Design 表头与表体分离在兄弟 `<table>` 的结构），因此语义与普通字段一致；表单项标签或包裹 `<label>` 优先级更高。
- **条件渲染字段**（父级下拉/单选赋值后才出现的区块，如「生产性企业→产线数量」）：填充完成后自动补扫并补填新出现的字段，无需手动二次识别。
- **折叠区/一屏放不下的字段**：识别阶段边滚边扫，把滚动后才懒挂载或才进入视口的字段一并累积进字段表；填充阶段再滚一遍补填新出现的字段，全部完成后恢复页面原滚动位置。前提是「滚到即渲染」；`el-table-v2` 这类虚拟滚动表格的未渲染行与「+ 添加一行」的动态行仍只覆盖当前已渲染部分（列入 V1.1）。

## 4. 规则目录（内置 + 用户自定义，按优先级匹配）

一条规则就是一份声明式数据：`{ id, name, group, keywords, gen, mark?, disabled? }`。匹配时把 label / placeholder / name / id 拼成 haystack 逐条试关键词，**首个命中者胜**。关键词有两种写法：普通文本（转义后做子串匹配，忽略大小写）与 `/…/` 包起来的正则（如 `/bank\s*card/`、`/[（(]元[）)]`）。

排序即优先级，分两层：**用户自定义规则整体在前，内置规则在后**；同层内**关键词越长越具体者在前**（「手机」先于「电话」、「信用代码」先于「账号」、「邮箱」先于「地址」）。停用的规则不参与匹配。

| 分组 | 内置规则 | 生成方式 |
|------|---------|---------|
| 联系人 | `phone` 手机号、`landline` 固定电话、`email` 电子邮箱、`cnName` 中文姓名、`gender` 性别、`education` 学历 | 号段池 + 8 位数字；区号-7~8 位；名池 + 数字 @ 域名池；姓 + 1~2 个名用字；候选池随机 |
| 企业与证照 | `creditCode` 统一社会信用代码、`idNumber` 居民身份证号、`bankCard` 银行卡号、`passport` 护照号、`company` 企业名称 | 校验位算法（GB 32100 / GB 11643 / Luhn）；城市 + 字号 + 行业 + 形式词库。`passport` 关键词留空，只由「证照类型」联动选中，避免「护照有效期」被判成号码 |
| 地理 | `region` 省市地区、`address` 详细地址、`zipcode` 邮政编码、`lnglat` 经纬度 | 真实三级行政区划；区划 + 路名门牌；`{num:1-6}{d:5}`；按省市质心离线推导（`lnglat` 优先级高于 `region`/`address`） |
| 数字 | `amount` 金额、`integer` 整数 | 两位小数金额 / 整数。`integer` 排在 `date` 前，故「实际运营时间（年）」按年数而非日期；区号需显式命中，它常落在 `el-input-number` 上，而数字控件的兜底是 `amount`，会生成 `34031.76` 这类小数写进整数框 |
| 日期 | `date` 日期 | `YYYY-MM-DD` / `YYYY-MM-DD HH:mm:ss`，方向默认「今天及以后」（上界一年）；**标签命中 `成立/出生/毕业/入职/注册` 时恒定生成过去的日期**（1960~2015），不受方向设置影响 |
| 文本 | `url` 网址、`paragraph` 段落备注、`generic` 兜底文本 | 段落取自句子池 2~4 句；兜底为 `test-{m:5}`。`generic` 无关键词，只在所有规则都没命中时用 |
| 选项 | `enum` 页面选项 | 不生成值，填充时从页面真实展开的候选里随机挑。无关键词，是选项类控件的兜底 |

`company` 与 `generic` 出厂带 `mark: true`：给生成值两端拼上用户设置的数据标记前后缀，便于事后检索自己造的数据。`mark` 是可编辑的规则属性——设置页实时列出当前带标记的规则，规则中心里可逐条勾选；人名/手机号/邮箱/地址/证照号等有格式或校验位约束，不要给它们开标记，加了必然过不了页面校验。

**每一条都可改写**：关键词、分组、生成方式、停用开关在规则中心里逐条可编辑，改坏了能「恢复默认」。用户规则与内置规则共用同一份数据结构，存储上内置规则**只在被改过时才落盘**（存 delta），所以「出厂态」= 本地没有这条覆盖记录。

## 5. 功能清单

### MVP（本次实施）

1. 按需注入 + Popup 弹窗主界面（识别 / 预览 / 编辑 / 重roll / 排除 / 单条与全量填充 / 清除全部 / 撤销 / 设置）。设置以窗内视图切换（设置 / ← 返回），不再开新标签页。打开弹窗只识别、绝不自动填充；填充与清除均需显式点击按钮。视觉上固定 400×600：顶部工具条只留「重新识别 / 填充全部」两个高频动作，破坏性的「清除全部」与低频的「撤销 / 设置」下沉到底部（撤销在没有可撤销快照时禁用，避免点了没反应）；字段列表前是「全选」复选框 + 「已选 N/M」计数（部分选中呈 indeterminate），每行带序号，标签认不出来时显示灰色「未命名」而不是拿「页面选项」这类内部规则名冒充字段名；每个字段一张圆角卡片（悬停微抬升）、kind 标签按控件大类着色（选择类紫、日期类青、上传类琥珀、弹窗选择绿、开关橙、其余灰）以便在几十行里一眼分辨，语义标签蓝色、**`generic`（词典未命中）灰显**让用户立刻看出哪些字段靠的是兜底；填充失败的卡片整行转红底红字并保留页面原话，行内图标按钮（换一个 / 填充此字段）默认弱化、悬停该行才显形；**上传类字段的值只读展示**（文件名由文件池/合成决定，手改无意义）；状态文字按结果着色（失败红、部分控件无法清空琥珀），工具条的「跳过 N 个」可点击并滚动到跳过原因列表。
2. 上表 1~22 全部控件类型的识别与填充（Element Plus / Ant Design / 原生 / ARIA role 四层选择器）。表格内可编辑单元格按**列头**取标签，因此联系人/银行账户这类子表里的字段语义与普通字段一致。
3. 中文合规数据生成：姓名、手机、座机、邮箱、身份证（校验位）、信用代码（校验位）、护照、银行卡（Luhn）、真实三级行政区划、地址、经纬度坐标（离线按省市质心推导，无网络请求）、公司名、日期/日期时间/范围、金额/数量、段落、URL、邮编、PNG/PDF 文件。全部由规则目录驱动，用户可用**模板 DSL** 自定义任意格式——字符类 `{d:8}` 数字 / `{n:12}` 大写字母加数字 / `{c:4}` 汉字 / `{s}` 自定义字符集，数量支持区间 `{d:3-6}`，取值支持 `{pool:词库id}`、`{num:1-999}`、`{num:1-500:2}`，日期支持 `{now}`、`{now:YYYYMM}`、`{now-30d:YYYYMMDD}`，`{{`/`}}` 输出字面大括号。
4. 覆盖模式开关：默认「只填空白」，可切换「覆盖已有值」。
5. 撤销：恢复最近一次填充前的值快照。
6. 一键清除：把识别到的字段全部置空——原生控件可靠清空；EP/AntD 下拉/级联/日期经「清除图标」清空（先聚焦/悬停揭示 × 再点击）；框架单选组无「取消选择」能力，计入「无法清空」并在状态栏提示。
7. **规则中心** + 上传文件池（规则中心 `RulesPanel` 与设置页 `SettingsPanel` 在 Popup 内嵌视图与选项页共用；设置页按「填充 / 随机数据 / 上传」分为三组，开关与输入即时保存、保存后原处回显「✓ 已保存」，随机数据组里列出当前带数据标记的规则并可直接跳到规则中心调整）。规则以「内置目录 + 用户 delta」的形式存在 `chrome.storage.local`（键 `ff.rules`，规则文本可能超出 `storage.sync` 单项 8KB 上限，故不放 sync），Popup 订阅 `storage.onChanged` 实时生效；老版本存在 `storage.sync` 里的散项设置（日期格式、邮箱域名、手机号段、企业后缀）在首次读取时自动迁移成对应词库覆盖并删掉旧键，用户不需要手动重配。规则中心里每条规则都能改名称、关键词、分组、生成方式，能停用、能新建、能「恢复默认」；生成方式有六种——模板 DSL、词库随机、数值区间、日期、内置算法（校验位号码 / 姓名 / 企业名 / 地区 / 地址 / 经纬度 / 金额 / 段落）、页面选项，编辑器里实时给三条样例预览，模板语法不合法时不落盘并把原因写出来。词库单独一个页签，内置词库（号段、区号、邮箱名/域名、企业字号/行业/形式、路名、句子池、性别、学历……）可整份覆盖，也能新建自定义词库供模板 `{pool:id}` 引用。规则文件可**导出 / 导入 JSON**（合并或替换两种模式），导入时逐条校验形状，坏条目跳过并把原因列出来，便于团队间共享一套造数规则。
   文件池允许预设本地上传文件（单个 ≤2MB、最多 10 个）存入 `chrome.storage.local`（需 `unlimitedStorage` 权限），填充上传控件时按 `accept` 优先匹配真实文件，无匹配再回退合成 PNG/PDF；**池文件若不满足字段声明的门槛（「单张 50KB 以内」「尺寸大小为：480*480px」这类提示）会被自动跳过改用合成文件**，避免用户预置的大图被页面静默拒收——设置面板已就此给出说明文案。合成图的外观可在「上传」组里调整：文字内容（留空不写）、九宫格位置、默认尺寸（留空 240×160），右侧带实时预览；字段提示声明了尺寸时仍以字段为准。
   邮箱域名词库**只收 `@` 后面的部分**（如 `example.com`）；误填完整邮箱（如 `test@example.com`）时自动只取域名并在设置页给琥珀色即时提示，非法填写回退内置域名池——保证生成的邮箱始终只有一个 `@`、能过页面格式校验。
   **数据标记是「数据归属标记」**：多人共用一套测试环境时需要事后搜出自己造的数据，填前缀 `qa-` 后企业名称变成 `qa-宁波星辰科技有限公司`、词典未命中字段的兜底值 `test-xxxxx` 变成 `qa-test-k3j2h`；**原样拼接、不自动补分隔符**（要 `-` 自己写进前后缀），**作用于规则中心里勾了「贴数据标记」的规则**（出厂只有企业名称与兜底文本开启，设置页实时列出当前范围），**不做长度控制**（生成器读不到字段的 `maxlength`），值会变长，超长字段可能被页面截掉末尾标记，已在使用文档里明示；号码与证件类规则不要开标记，格式校验会失败。
8. 跨字段联动：证照/证件号码跟随证照/证件类型的当前选择生成对应格式（统一社会信用代码→18 位信用代码、居民身份证→18 位身份证、护照→护照号、其他→通用串）；经纬度跟随**同一表单内**的地址/地区字段生成对应坐标（按表单作用域配对，多表单页不会错链；地址或坐标任一方重roll 时另一方同步）；「注册资本/实缴资金（单位:元）」类字段按整数元生成以通过金额校验。
9. 长表单全覆盖：条件渲染字段填充后自动补扫补填；一屏放不下、需向下滚动才可见（或滚动后才懒挂载）的字段在识别阶段边滚边扫一并累积，填充阶段再滚一遍补填，结束后恢复页面原滚动位置；视口外控件填充前先滚入视口，避免下拉面板/弹窗定位错乱。
10. demo 页（原生 + Element Plus 真实组件，含「注册地址 + 禁用经纬度」联动样例、「企业生产类型→v-if 揭示产线数量」条件渲染样例、联系人子表（列头标签）、三个弹窗选择样例（清算会员号=单选列+页脚确定；税收编码=无页脚、行内「选择」链接；跟进组织=`el-tree` 树形，父节点是组织组、叶子才是公司）、滚动后懒挂载区）+ 单元测试（生成器校验位与自定义规则、语义推断、证照联动、经纬度联动与禁用白名单、控件分类、原生填充与清除、表格列头标签、滚动累积、弹窗选择（含随机与树形）、落地审计）。
11. 一键自检（开发期能力，不在扩展 UI 里、用户无需操作）：注入 dev harness 后调用 `window.__ff.selfCheck()`，把「扫描 → 生成 → 填充」跑一遍，再用一张**独立手写的期望表**（标签 → 期望语义 → 值形态）审计页面上的落地值，输出违规清单（空值 / 占位项泄漏 / 语义未命中 / 值形态不符 / 图片字段传了非图片 / 上传尺寸不符 / 填充报错）。目的是抓「面板报成功但页面值为空或值不合规」这类静默失败——真实页面上用户只看得到红字，自检让这类缺陷在 demo 上先暴露。
12. 填充后页面校验回读：填充结束约 0.4 秒后，对这次真正写过值的字段回读页面自身的校验提示（Element Plus / Ant Design / iView / 常见 `is-error`、`has-error`、`aria-invalid` 等），在弹窗里标黄并显示页面原文，状态栏与扩展自身的填充失败（标红）分开计数。只查尝试过的字段，未参与填充的字段上原有的红字不计入；静态说明文字（`.help-block` 等）不被误判为错误。只在填充结束读一次，之后页面再弹的校验不回写。

## 6. 非功能需求

| 维度 | 指标 |
|------|------|
| 空闲开销 | 0：无常驻 content script，无 MutationObserver 常驻 |
| 识别耗时 | 500 控件页面 ≤ 300ms（单次遍历 + 索引化 label 查找） |
| 填充体验 | 原生控件批量同步填充不阻塞主线程（分片 rAF）；组件库控件逐个异步（需等下拉展开） |
| 内存 | 字段列表与元素引用仅在弹窗会话期持有，重扫/关弹窗即释放 |
| 隐私 | 全部本地生成，无任何网络请求；权限 scripting/storage/activeTab + host_permissions `<all_urls>`（仅为按需注入任意业务页，不发起网络请求） |
| 兼容 | Chrome 116+；React 18/19、Vue 3、Element Plus、Ant Design 4/5、原生表单 |

## 7. 非目标

- 不自动提交表单、不绕过验证码、不抓取线上真实数据。
- 不做 Firefox/Safari 适配（MV3 API 以 Chrome 为准）。
- 不做「保证通过服务端校验」的承诺（仅保证常见前端格式校验可通过）。

## 8. MVP 验收标准

1. demo 页（原生区 + Element Plus 区）打开弹窗即识别，但**绝不自动填充**；点「填充全部」后所有控件值为合规随机数据，Vue/React 状态同步（提交可取到值）。
2. demo 页长表单专项：联系人子表按**列头**语义填入（姓名=中文名、手机号=合规号段、电子邮箱=邮箱格式、区号=整数而非小数）；三种弹窗选择形态都能选中一条记录并回填——「清算会员号」（单选列 + 页脚确定）、「税收编码」（无页脚、无单选列，靠 `操作` 列的「选择」链接提交）与「跟进组织」（`el-tree` 树形，父节点是组织组、只有叶子能提交），且**多次填充选中的记录不总是同一条**（叶子间随机），弹窗遮罩关闭不阻塞后续字段；滚动后才懒挂载的字段（供应商产能/产线/合作客户/意向物料）也被识别并填入 Vue 模型；全部填充结束后页面滚动位置复位到进入前；**带尺寸门槛的上传样例**（商品主图，提示「尺寸大小为：480*480px」且 `before-upload` 严格校验真实像素）必须通过校验进入 fileList，不能出现「红字提示不能为空、文件却没上传」。
3. 截图同类页面（多步骤长表单准入风格）人工验证：识别覆盖率 ≥ 90% 可见控件，误填率 0（disabled/只读不被填，只读但有选择按钮的按弹窗选择处理）。弹窗选择字段**要么有值、要么红字报错并附现场清单**（行数/叶子数/表数/是否自关/点过哪些控件/读到的记录文本），不允许「面板显示成功但字段为空」的静默失败——用户截图红字即为下一轮修复的充分证据。
4. 填充后点「撤销」，页面恢复填充前状态（上传项除外，文档中明示）。
5. 填充后点「清除全部」，识别到的字段全部置空；框架单选组等不支持清空的控件在状态栏计入「无法清空」并如实提示。
6. 在 Popup 设置页（点「设置」进入窗内视图，「← 返回」回到字段列表；选项页为兜底入口）进入规则中心，新建一条「订单号」规则（关键词 `订单号、orderNo`，生成方式 = 模板 `{n:12}`）并保存后，重新识别时带「订单号」的字段应命中这条自定义规则、生成 12 位大写字母加数字；改内置规则的关键词或词库（如把手机号段换成自己的号段池）后，重新识别生成的数据随之改变；停用一条规则后它不再参与匹配；「恢复默认」把内置规则退回出厂态；自定义规则优先级高于内置规则。导出的 JSON 能在另一台机器上导入（合并模式保留本地已有规则、替换模式先清空），坏条目跳过并列出原因。**名称前后缀填 `qa` 后，名称类兜底文本应为 `qatest-xxxxx`、企业名称应以 `qa` 开头，而人名/手机号/邮箱/地址/证照号保持各自格式不变**（加了标记会过不了页面校验）。同一设置页可维护上传文件池，加入文件后填充上传控件应优先注入按 `accept` 匹配的真实文件，池为空或无匹配时回退合成 PNG/PDF；**池文件违反字段声明门槛时（如在写着「单张 50KB 以内」的字段上放 800KB 的图）应自动改用按尺寸合成的文件，页面不再弹拒收提示**（已在 demo 页真实浏览器验证三场景；真实业务系统的门槛文案能否被解析仍待复测）。同页「合成图片」可改文字内容、九宫格位置与默认尺寸（留空 240×160），右侧预览实时更新；**字段声明了尺寸时以字段为准**，配置只作用于没写尺寸的字段。
7. `pnpm build` 通过、`pnpm test` 全绿；加载 dist 无 console error。
8. demo 页一键自检基线：`scanned 61 / fillable 59 / checked 59`（新增树形弹窗样例「跟进组织」后由 60/58/58 递增），连续两次运行结果一致；违规清单只允许两条已知项——「供应商资质图」的 `fill-error`（设计好的负样例，只收 jpeg，用以验证拒收自报）与「供应商产线」的 `semantic-miss`（该字段究竟是数字还是文字描述待业务确认）；不得出现 `empty`、`placeholder-leak`、`state-mismatch` 这类「面板成功但页面没值」的违规。
9. 日期区间开关：默认（勾选）状态下填充「有效期」这类非历史日期字段，值不早于今天且不超过今天+1 年，日期范围两端都在未来；「成立日期 / 出生日期 / 注册时间」等历史语义字段无论开关状态都落在过去。取消勾选并保存后，同一字段可以生成过去的日期。老用户的存量设置升级后开关应为勾选态且原有文本规则不丢。（已在 demo 页用 harness 采样 40 次 + 实际填充读回模型验证，设置界面用桩页验证；生产链路即 content 从 `chrome.storage.sync` 读规则这一段待用户重载扩展后在真实页确认。）
10. 填充后校验回读：在表单里预置一个必填但生成值通不过页面校验的字段（如页面规则要求固定格式），填完后该字段应标黄并在行内显示页面自己的错误原文，状态栏汇总「页面校验未通过」数量；扩展自身没填成功的字段仍标红，两类分开计数。未参与这次填充的字段上原有的红字不得计入。真实业务页（Element Plus）的提示读取待用户重载扩展后复测。
